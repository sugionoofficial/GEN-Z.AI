# Kredensial Opus di Supabase

1. Jalankan `supabase/opus-credentials.sql` dan `supabase/opus-credential-credit-status.sql` pada project aplikasi. Skrip slot mempertahankan kredensial yang sudah ada; migrasi status menambahkan indikator kredit per token. Deploy aplikasi setelah migrasi selesai.
2. Pastikan Worker memiliki `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` dan `PROVIDER_CREDENTIAL_ENCRYPTION_KEY` (atau `API_KEY_ENCRYPTION_SECRET`). Kunci enkripsi harus tetap sama agar data bisa dibaca. Rotasi refresh token memerlukan konfigurasi vault OAuth yang sudah ada.
3. Login sebagai admin/owner. Di Black Box, buka login Opus, selesaikan login dan salin JSON token lengkap. Di **Kredensial Opus**, tempel JSON ke input rahasia `OPUS_AUTH_TOKEN_1`, lalu Simpan. Gunakan + dan − atau masukkan nomor pada kolom Nomor slot untuk memilih slot pada satu formulir; label Terakhir menunjukkan nomor slot tersimpan terbesar. Untuk mengganti token, pilih Edit pada slot tersimpan, tempel token baru dan Simpan. Tombol Hapus pada daftar menghapus slot setelah konfirmasi.
4. Generate video dan provider Opus di Studio Medsos membaca slot Supabase dalam urutan nomor. Studio Medsos tidak fallback ke token Worker; jika vault kosong atau gagal dibaca, fitur memberi error. Token lama tidak dipindahkan otomatis: masukkan setiap akun ke slot Supabase dan uji sebelum menghapus secret Cloudflare yang sudah tidak digunakan fitur lain.

Token dienkripsi AES-256-GCM; tabel dibatasi untuk service role. Di halaman Kredensial Opus, badge merah berarti Opus secara eksplisit melaporkan kredit habis, hijau berarti generate berhasil dengan token itu, dan abu-abu berarti belum ada hasil pasti. Setiap generate Studio Medsos selalu mulai dari slot 1; slot yang habis dilewati berurutan. Mengganti token mereset badge ke abu-abu. Sistem antrean yang sudah ada melakukan perpindahan untuk kesalahan yang aman dicoba ulang (misalnya kredit habis atau semua slot gagal autentikasi), menunggu lima menit setelah satu putaran dan mencoba ulang tiga kali. Kesalahan lain, termasuk hasil submit yang tidak pasti, tidak diulang secara buta untuk menghindari job dan biaya ganda. Jangan hapus atau ubah slot saat ada job Opus yang masih berjalan karena posisi slot dipakai untuk polling. Antrean menunggu berjalan di browser; jangan tutup halaman selama proses tersebut. Tidak ada batas jumlah slot tetap pada aplikasi, tetapi tetap berlaku batas infrastruktur.
