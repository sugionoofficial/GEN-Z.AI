# Kredensial Opus di Supabase

1. Jalankan ulang `supabase/opus-credentials.sql` di SQL Editor project aplikasi. Skrip ini mempertahankan kredensial yang sudah ada dan menetapkan nomor slot stabil. Deploy aplikasi setelah migrasi selesai.
2. Pastikan Worker memiliki `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` dan `PROVIDER_CREDENTIAL_ENCRYPTION_KEY` (atau `API_KEY_ENCRYPTION_SECRET`). Kunci enkripsi harus tetap sama agar data bisa dibaca. Rotasi refresh token memerlukan konfigurasi vault OAuth yang sudah ada.
3. Login sebagai admin/owner. Di Black Box, buka login Opus, selesaikan login dan salin JSON token lengkap. Di **Kredensial Opus**, tempel JSON ke input rahasia `OPUS_AUTH_TOKEN_1`, lalu Simpan. Gunakan + dan − untuk memilih nomor slot pada satu formulir. Untuk mengganti token, pilih Edit pada slot tersimpan, tempel token baru dan Simpan. Tombol Hapus pada daftar menghapus slot setelah konfirmasi.
4. Generate video membaca slot Supabase dalam urutan nomor, tanpa fallback token Worker atau provider lama. Token lama tidak bisa dipindahkan otomatis: masukkan semuanya dan uji sebelum menghapus secret Cloudflare lama. Fitur lain mungkin masih memakai konfigurasi lama; jangan hapus secret sampai seluruh penggunaan lain telah dimigrasikan dan diuji.

Token dienkripsi AES-256-GCM; tabel dibatasi untuk service role. Sistem antrean yang sudah ada melakukan perpindahan untuk kesalahan yang aman dicoba ulang (misalnya kredit habis atau semua slot gagal autentikasi), menunggu lima menit setelah satu putaran dan mencoba ulang tiga kali. Kesalahan lain, termasuk hasil submit yang tidak pasti, tidak diulang secara buta untuk menghindari job dan biaya ganda. Jangan hapus atau ubah slot saat ada job Opus yang masih berjalan karena posisi slot dipakai untuk polling. Antrean menunggu berjalan di browser; jangan tutup halaman selama proses tersebut. Tidak ada batas jumlah slot tetap pada aplikasi, tetapi tetap berlaku batas infrastruktur.
